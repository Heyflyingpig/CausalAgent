一、结论与三阶段顺序

阶段二拆成三个可独立验收的阶段：

阶段核心目标主要交付完成标志
第一阶段：观测底座与日志契约先理解并引入 Grafana 日志链路，统一日志分类和字段Alloy、Loki、Grafana；JSON 日志契约；分类与隐私规则测试日志可从容器进入 Loki，并能在 Grafana 检索
第二阶段：逐模块布点与上下文贯通人工判断哪里真正需要 logger，并补齐跨进程关联布点清单；Web/Worker/Monitor/MCP 日志；request/job/node/tool 关联受控故障能准确指出服务、模块和调用上下文，正常业务不制造噪声
第三阶段：验证与管理员后台接入先在 Grafana 验证正确性，再把必要能力接入管理员系统验证矩阵；Grafana 排障视图；Flask 受控查询；Vue 日志统计与搜索同一日志在 Grafana、API、Vue 三处结果一致，管理员可定位问题来源

依赖关系：

阶段一：先让日志链路可用并冻结契约
  → 阶段二：再决定并补齐 logger 布点
    → 阶段三：验证日志正确后接入管理员系统

二、确定的技术栈与职责边界

层级技术本项目职责
日志生产Python logging • JSON Formatter + contextvarsFlask、worker、monitor、Agent/RAG 与 MCP 输出单行结构化 JSON 到 stderr；自动注入关联上下文
采集与处理Grafana Alloy发现 Docker 容器、采集 stdout/stderr、解析 JSON、丢弃无用字段、补充低基数标签并批量发送
存储与查询Grafana Loki + LogQL保存日志流、按时间与标签检索、对 JSON 字段筛选并生成统计；不把运行日志复制进 MySQL
工程排障Grafana Logs Drilldown / Explore开发和运维进行深度搜索、模式分析、上下文查看与 Debug；这是完整日志界面
管理端查询现有 Flask 管理 API把固定筛选参数转换为白名单 LogQL；限制时间范围、结果数、超时和并发；浏览器不得提交任意 LogQL
管理端展示现有 Vue 3 + TypeScript + Element Plus + Vite展示错误趋势、来源分布、最近异常、条件搜索和去敏详情，并提供“在 Grafana 中打开”入口
权限与审计现有 MySQL admin_audit_events继续记录管理员读取敏感日志详情和导出行为；不承担日志主存储

关键架构决定

  1. 采用 Alloy + Loki + Grafana，不新建 operational_log_* MySQL 表。当前目标是可搜索和可定位，不是工单处置；双写 MySQL 会增加故障递归、迁移、容量与一致性成本。
  1. Grafana 是深度 Debug 主界面，管理员后台是轻量入口。后台不复制 Grafana 的全部能力，只提供产品需要的统计、筛选、搜索和详情。
  1. 只允许后端生成 LogQL。Vue 只传递时间、级别、服务、分类、事件码、关键词、request ID、job ID 等白名单参数。
  1. 高基数字段不做 Loki 标签。request_id、job_id、user_id、session_id、node、tool、异常指纹保留为 JSON 字段；标签仅使用 environment、service、level、category 等低基数字段。
  1. 版本使用经过验证的固定版本。Compose 与镜像不得使用 latest；Grafana、Loki、Alloy 在隔离环境验证兼容后再固定版本号。

三、统一日志契约与分类计划

3.1 必要字段

每条结构化日志至少包含：

  • timestamp：UTC、RFC3339 格式。
  • level：debug/info/warning/error/critical。
  • service：web/worker/monitor/mcp/maintenance。
  • environment、instance、logger、module、function。
  • 稳定 event_code，例如 db.replica_fallback、job.node_timeout、mcp.tool_failed。
  • category：system/job/security/dependency。
  • 去敏后的 message、可空 exception_type 与有界堆栈。
  • 可空 request_id、user_id、session_id、job_id、worker_slot、node、tool。
  • details 仅允许白名单键，并设置序列化大小上限；超限写入 truncated=true。

3.2 分类口径

分类记录场景不应记录为异常的场景
system数据库连接失败、副本回退、连接池耗尽、进程启动失败、监控采集失败正常启动信息、周期性健康检查成功
job任务失败、节点超时、重试耗尽、路由或工具降级、结果质量下降正常进度、正常完成、用户取消、算法正常发现环路
security禁用账号登录、达到阈值的连续失败、越权、CSRF 或重新认证异常单次会话过期、普通用户误入管理员地址、普通表单校验
dependencyLLM、RAG、MCP、外部模型或文件依赖不可用、超时或返回无效结果有明确产品兜底且对结果无影响的预期空结果

3.3 隐私与安全边界

  • 禁止记录密码、Cookie、Session/CSRF Token、API Key、数据库口令和完整连接 URL。
  • 禁止记录完整用户提示词、完整 LLM 输出、文件正文、CSV 内容、SQL 参数值和异常局部变量。
  • 只保留稳定内部 ID、长度、shape、错误码和去敏摘要；堆栈仅保留有限代码帧。
  • JSON 格式化失败或 Loki 不可用时，业务仍输出一条最小去敏 stderr 证据，不递归记录日志系统自身错误。
  • Alloy 访问 Docker 日志的权限必须隔离；生产环境评估只读 socket proxy 或受限文件采集，不能把 Docker 管理能力暴露给应用网络。

四、第一阶段：观测底座与日志契约

目标

先把 Grafana 日志系统跑通，并冻结日志字段、标签、分类、保留和隐私规则；暂不大规模修改业务 logger，也不接管理员页面。

实施任务

  • 在开发/隔离 Compose 中加入 Loki、Grafana、Alloy，并建立独立网络、持久卷、健康检查和资源上限。
  • 配置 Alloy 容器发现与日志读取，解析 Docker 包装字段和应用 JSON，补充 environment/service/level/category 标签。
  • 配置 Loki 单节点开发模式、查询限制、摄入限制和初始保留周期；保留期必须可配置且基于实测日志量调整。
  • 在 Grafana 配置 Loki 数据源，建立基础 Logs Drilldown/Explore 入口和最小看板：错误总量、按服务/级别/分类分布、最近错误。
  • 编写共享 JSON 日志格式器、上下文 Filter/Adapter、集中脱敏器和大小限制；先用独立测试脚本验证。
  • 冻结日志字段字典、事件码命名规范、级别判定规则和“应记录/不应记录”示例。
  • 盘点现有日志：来源、格式、敏感字段、重复率、每分钟峰值和磁盘/保留预算。
  • 验证 analysis_jobs 是否已有原始 request_id；若缺失，仅追加这一项最小 Alembic 变更，用于 HTTP → job → worker 关联。

交付物

  • 可启动的 Alloy + Loki + Grafana 开发栈与固定版本配置。
  • 统一日志契约、分类表、事件码规范、标签策略和隐私规则。
  • Grafana 最小排障视图与一组可重复发送的测试日志。
  • 现有日志盘点报告和阶段二 logger 布点模板。

验收门槛

  • Web、worker、monitor、MCP 四类测试日志都能被 Alloy 采集并在 Loki 检索。
  • Grafana 可按服务、级别、分类筛选，并能解析 request/job 等 JSON 字段。
  • Alloy 或 Loki 重启后不会造成采集位置明显回退或日志风暴；失败状态可观察。
  • request_id、job_id 等高基数字段没有成为 Loki 标签。
  • 脱敏测试确认秘密、提示词、LLM 输出、文件正文和 SQL 参数不会进入日志。
  • 正常业务 INFO 与 WARNING/ERROR 的边界已有评审结论，尚未确认的事件码不进入批量布点。

五、第二阶段：逐模块布点与上下文贯通

目标

按模块人工判断“为什么需要这条日志”，把 logger 放在真正有诊断价值的边界；Codex 可用于扫描、提出候选和检查遗漏，但最终级别、字段和布点由开发者评审确认。

实施方法

每个候选日志点先填写一行布点清单：

模块/位置失败或降级事实事件码/级别/分类必要字段为何能帮助 Debug为何不会制造噪声
示例：worker 节点超时边界节点在限定时间内未完成job.node_timeout / error / jobjob、worker、node、elapsed可定位具体任务与图节点只在最终超时或重试耗尽时记录

实施任务

  • Web：接入未处理异常、数据库/事务失败、明确基础设施降级和达到规则阈值的安全事件。
  • Worker/Agent：接入 job 失败、节点超时、重试耗尽、工具/路由降级、结果质量下降和 worker/MCP 初始化失败。
  • Monitor：接入采集失败、快照写入失败、命名锁异常和配置降级；预期 unknown 不自动升级为 ERROR。
  • MCP：改为单行 JSON stderr；工具结构化错误由父 worker 补齐 job/tool 上下文，管理端不扫描 mcp_server.log。
  • 使用 contextvars 贯通 Flask request → job 创建 → worker 领取 → LangGraph node → MCP tool；在 finally 中可靠清理。
  • 验证 asyncio task 与 asyncio.to_thread() 的上下文传播；不依赖未经测试的默认行为。
  • 逐项删除或改写现有敏感日志、重复日志和把正常业务结果记录为 WARNING 的日志。
  • 为每个事件码增加受控故障测试；抽样核对源代码位置、JSON 字段、Alloy 解析结果与 Loki 内容。

优先布点顺序

  1. 会导致请求或任务失败的最终边界。
  1. 会改变结果质量或触发降级的边界。
  1. 无法仅靠返回值定位的跨进程边界。
  1. 安全规则达到明确阈值的边界。
  1. 普通成功路径仅保留少量必要 INFO，不做逐函数日志。

交付物

  • 经人工确认的 logger 布点矩阵。
  • Web、worker、monitor、Agent/RAG、MCP 的结构化日志实现。
  • request/job/worker/node/tool 关联链路与自动化测试。
  • 敏感日志整改清单与噪声基线。

验收门槛

  • 受控触发 Web 500、worker 失败、节点超时、RAG 降级、monitor 失败和 MCP 工具错误时，均出现唯一、可解释的事件码。
  • 从 request ID 或 job ID 可以定位到对应 worker、node 与 tool 日志。
  • 两个并发请求、两个 worker slot 和连续任务之间不会串上下文。
  • 数据库、Alloy 或 Loki 不可用时不递归、不死锁、不无限重试，原业务失败语义不被改变。
  • 正常登录、聊天、上传、任务执行和算法正常结果不会产生 WARNING/ERROR 噪声。
  • 抽样日志不包含秘密、完整提示词、完整 LLM 输出、文件正文或 SQL 参数。

六、第三阶段：验证与管理员后台接入

目标

先用 Grafana 验证日志是否真实、完整、可检索，再把产品真正需要的统计与搜索接入现有管理员系统；不把 Grafana 重做一遍。

A. Grafana 正确性验证

  • 为 Web、worker、monitor、RAG、MCP、数据库降级分别定义可控故障场景和期望事件码。
  • 在 Grafana 中核对时间、服务、级别、分类、模块、request/job/node/tool 与源代码事实一致。
  • 验证同一故障的重复日志数量、异常模式和检索耗时；调整事件码与布点，直到能稳定定位问题来源。
  • 建立最小工程视图：错误趋势、服务分布、事件码排行、最近错误，以及按 request/job 下钻。
  • 记录 Grafana 的标准查询示例和排障步骤，避免依赖个人记忆。

B. Flask 受控查询 API

建议提供三个只读端点：

  • GET /api/admin/logs/summary：指定时间范围内按级别、服务、分类和事件码统计。
  • GET /api/admin/logs/search：按白名单筛选条件分页查询日志摘要。
  • GET /api/admin/logs/fields：返回允许的服务、级别、分类和事件码选项。

接口约束：

  • 后端生成固定 LogQL 模板；禁止浏览器传入完整 LogQL。
  • 时间范围使用白名单，默认 1 小时，第一版最大 24 小时；更长调查跳转 Grafana。
  • 单页默认 50、硬上限 200；设置 Loki 查询超时、响应大小和并发上限。
  • 列表返回去敏摘要；完整 JSON/堆栈仅在明确点击后按上限返回。
  • 未登录返回 401，非管理员返回 403；敏感详情与导出写入 admin_audit_events。
  • Loki 不可用时返回明确降级状态，不回退扫描 Docker 文件或 MySQL。

C. Vue 管理端日志页

新增 /admin/logs，只包含：

  • 错误数量趋势、按服务/级别/分类分布、最近高严重度日志。
  • 时间范围、服务、级别、分类、事件码、关键词、request ID、job ID 筛选。
  • 日志摘要表和去敏详情抽屉。
  • 加载态、空态、超时、Loki 不可用、权限失效和结果截断提示。
  • “在 Grafana 中打开”链接，把当前筛选条件带到 Grafana 深度排障界面。

第一版不做自定义 SSE；页面使用手动刷新或有上限的短周期轮询。实时追踪继续使用 Grafana，避免占用 Flask/Gunicorn 长连接。

交付物

  • Grafana 验证矩阵、标准排障查询和最小看板。
  • Flask 受控日志统计/搜索 API 与权限、限流、超时、审计测试。
  • Vue 日志统计与搜索页面及生产构建产物。
  • Grafana/API/Vue 三方一致性验证报告。

验收门槛

  • 同一已知日志在 Grafana、Flask API、Vue 页面中的时间、级别、来源、事件码和关联 ID 一致。
  • 管理员可在三步内从统计异常定位到具体服务、模块和 request/job。
  • 搜索、分页、时间范围与结果截断准确，不出现漏页、重复或无界查询。
  • 普通用户无法访问页面或 API；浏览器无法构造任意 LogQL。
  • Loki 查询慢、超时或不可用不会拖垮普通用户请求，并有明确错误态。
  • Vue typecheck、单元测试、Mock E2E、生产构建和隔离环境核心 E2E 通过。

七、本阶段明确不做

  • 不做 incident 的确认、分派、解决、重开、静默、备注或调查保留。
  • 不做日志工单、负责人体系、批量处置或告警值班系统。
  • 不在管理员后台开放任意 LogQL、SQL、Loki 删除、保留期修改或宿主机文件读取。
  • 不新建 MySQL 运行日志、异常聚合或处置动作表。
  • 不把 analysis_job_events、admin_audit_events 与运行日志混成一个数据源。
  • 不在第一版加入 Kafka、消息中间件、完整 OpenTelemetry trace 或自研实时 SSE。
  • 日志告警、自动通知和复杂长期留存作为后续独立阶段，只有实际需求和容量数据支持时再启动。

八、依赖、风险与停止条件

实施前依赖

  • 阶段一管理员鉴权、Vue 管理端、Flask API 与 X-Request-ID 保持可用。
  • 确认部署环境允许运行 Grafana、Loki、Alloy，并明确持久卷、端口和访问控制。
  • 只读盘点真实日志量、峰值速率、可接受保留天数和可用磁盘。

主要风险与缓解

  • Loki 标签基数失控：仅使用低基数标签，高基数 ID 留在 JSON 字段；上线前检查 stream 数量。
  • Docker 日志权限过大：隔离 Alloy，限制网络与宿主权限；生产优先评估受限 socket proxy 或只读日志文件方案。
  • 日志泄密：集中脱敏、字段白名单、大小上限、固定测试语料和抽样审查共同兜底。
  • logger 布点过多：所有新增 WARNING/ERROR 必须在布点矩阵说明 Debug 价值和降噪条件。
  • 管理员查询拖垮 Loki：固定查询模板、短时间窗、结果上限、超时、并发限制和 Grafana 深度查询分流。

停止条件

  • Alloy/Loki/Grafana 基础链路不稳定，或版本兼容性未验证。
  • 真实日志量、磁盘预算或保留周期仍未知，却准备进入生产。
  • 脱敏测试未通过，或仍可能输出完整提示词、LLM 结果、文件正文和秘密。
  • request/job 上下文无法可靠传播，却准备宣称可全链路定位。
  • Grafana 中的日志与源代码事实对不上，却准备接入管理员后台。
  • Flask 只能接受任意 LogQL，或无法限制时间、结果量、超时与并发。

九、阶段二总体验收标准

  • Alloy、Loki、Grafana 的职责与配置已固定，日志链路在重启和故障场景下行为已知。
  • 日志契约、分类、事件码、标签和隐私规则已冻结并有自动化测试。
  • Web、worker、monitor、Agent/RAG、MCP 的关键故障可被检索，正常业务不会制造异常噪声。
  • request ID 和 job ID 可以关联到 worker、node 和 tool。
  • Grafana 能完成深度排障；管理员后台能完成必要统计、搜索、详情与跳转。
  • 管理员查询受权限、白名单、时间窗、结果量、超时、并发和审计保护。
  • 不引入日志处置系统、MySQL 运行日志双写或不必要的实时链路。
  • README、AGENTS、Compose、环境示例、隐私说明、运维手册和管理员前端构建产物与实现一致。

十、技术参考

  • Grafana Alloy：采集 Docker 日志
  • Grafana Loki HTTP API：query_range、labels 与 tail
  • Grafana Logs Drilldown：无需先编写 LogQL 的日志探索
