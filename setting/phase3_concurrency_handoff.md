# 阶段三并发治理设计交接

本文仅冻结下一阶段的设计输入，不属于阶段一运行契约，也没有在 3.2 migration 或代码路径中启用。

## 1. Worker fencing token

任务每次成功领取时递增不可回退的 `lease_generation`，并把 `(job_id, worker_id, lease_generation)` 作为租约身份。心跳、事件、checkpoint 关联写入和终态更新都必须在 SQL `WHERE` 中同时匹配当前 worker、generation 与 `status='running'`；旧 worker 在租约被接管后影响行数为 0，并立即停止。

需要先验证领取、超时重领、进程崩溃和数据库重连的状态机，再决定字段、索引和迁移。不能只依赖时间戳或进程内锁。

## 2. 事件幂等键

为跨重试事件定义稳定 `event_uuid`，由任务执行尝试和逻辑事件序号生成或在首次产生时持久化，数据库建立唯一键。SSE 的递增行 ID 继续用于断线续传，但不充当跨尝试幂等键。

需要明确哪些事件允许同类型多次出现、重放如何返回原事件，以及 payload 去敏和大小上限。

## 3. Heartbeat 监督

监督器只根据数据库服务器时间、当前 generation 和明确阈值判定租约过期。回收前再次加锁复核，不由 Web 请求线程直接强制终止 worker。暂时网络抖动、数据库不可用与 worker 真失联必须区分，并为误判保留可观测指标。

## 4. 任务终态原子性

任务结果、最终事件、聊天消息落库和 `analysis_jobs` 终态要么在一个数据库事务完成，要么采用可证明的 outbox/补偿协议。终态更新必须同时匹配 fencing token，并为成功重放返回同一终态，避免“任务成功但消息未保存”或重复消息。

进入实现前必须先补充失败矩阵、锁顺序、迁移升级/回滚、旧 worker 兼容窗口和隔离环境并发测试。本阶段禁止提前加入未被所有写路径校验的半套 token 或 heartbeat 字段。
